# 기술 문서

일본판 `RDZJ01` 기준입니다. 모든 정수는 빅 엔디언이고, 예외는 따로 적었습니다.

## 텍스트

게임 텍스트는 모두 압축 없는 Shift-JIS이며 제어 태그(`<n>` 줄바꿈, `<w=숫자>` 대기, `<p>` 넘김, `<kw>` 입력 대기, `<c=npc>` 색, `<BUTTON_A>` 버튼 그림 등)를 ASCII로 섞어 씁니다. `main.dol`에는 일본어가 없습니다.

| 파일 | 내용 | 도구 |
|---|---|---|
| `files/script/jp/*.sb` (83개) | 스테이지 스크립트의 대사·안내 | `sbfile.py`, `sbmeta.py`, `sbrefs.py` |
| `files/common/jp/bdat.bin` | 메뉴와 게임 데이터 표 51개 | `bdat.py` |
| `files/mov/jp/*.cap` (65개) | 컷신 자막 | `capfile.py` |

### 스크립트 `.sb`

- 헤더 `SB  ` 뒤 0x08에 섹션 오프셋 6개가 있습니다. 순서대로 바이트코드, (빈 표), 문자열 풀, 함수표, 심볼표, 스크립트 이름입니다.
- 문자열 풀: `u32 8`, `u32 개수`, `u32 오프셋[개수]`, 0으로 끝나는 문자열, 4바이트 정렬. 바이트코드는 문자열을 번호로 가리키므로, 풀을 다시 쓰고 뒤 섹션 오프셋만 밀면 됩니다.
- 바이트코드에서 `26 xx`(1바이트)와 `25 xxxx`(2바이트)는 문자열 참조, `4a xx`는 심볼 참조입니다. 심볼표 항목은 (모듈 이름, 함수 이름) 오프셋 쌍이며, 대사는 `menu.caption(대사, 음성 ID)`, 무전은 `menu.playRadio`, 안내는 `menu.tutorialmes`·`menu.sysmes`로 출력합니다. `deb.put`·`deb.msg`는 디버그 출력이라 번역하지 않았습니다.
- 함수표는 (이름 오프셋, 코드 오프셋) 쌍입니다. 대사가 속한 함수 이름과 음성 ID로 분류와 화자를 추정했습니다(`extract_text.py`).
- `.t`가 없는 스크립트 4개(`-nym_00`, `kns_05_old`, `roo08_00`, `ssk_00_b`)는 게임이 부르지 않는 것으로 보고 번역하지 않았습니다.

### 데이터 표 `bdat.bin`

- `u32 표 개수`, `u32 전체 크기`, `u32 표 오프셋[개수]` 뒤에 `BDAT` 표가 이어집니다. 모노리스 소프트의 제노블레이드(Wii)와 같은 계열입니다.
- 표 헤더: 0x06 이름 위치, 0x08 행 길이, 0x0A 행 위치, 0x0C 행 수. 0x20부터 열 정보(`u8 종류, u8 값 형식, u16 행 안 위치`)가 이어집니다.
- 값 형식 7은 문자열이며, 행에는 표 시작 기준 `u16` 오프셋이 들어갑니다. 문자열은 행 뒤에 중복을 합치지 않고 행 순서대로 두고, 표 끝은 16바이트로 맞춥니다.
- 주요 표: `menu`(타이틀·설정·스테이지 이름), `system_mes`(세이브 메시지), `file`(재해 파일), `retry`, `title`(칭호), `buy_wpn`, `item_list`, `rescue`, `result`, `tutorial_list`, `artwork`.

### 컷신 자막 `.cap`

`u16 0` 뒤에 `{00, u16 프레임, 문자열}` 이벤트가 반복됩니다. 문자열은 다음 이벤트의 `00`에서 끝나고, 빈 문자열은 자막을 지웁니다.

## 폰트

`font.bin`(대사), `CapFont.bin`(자막), `MenuFont.bin`(메뉴) 세 벌이 거의 같습니다.

- `\x01ARC` 헤더, 0x14에 문자표 길이, 0x18에 TPL 위치.
- 문자표: 1바이트 코드는 `코드, 폭`, 2바이트 코드는 `코드(2), 폭`. 표 순서가 글자 칸 번호입니다.
- 글자 그림: I4 TPL 9장(384×728). 칸은 24×28, 장당 16×26칸이며 3,723칸을 씁니다.

한글은 게임 텍스트에서 더 쓰이지 않게 된 한자의 코드와 칸을 빌려 씁니다(`korfont.py`). 맑은 고딕 20px을 4배로 그려 줄이고, 원본처럼 흰색·테두리 없음, 폭 20으로 넣습니다. 폰트에 없는 `·`는 폭 10으로 따로 그립니다.

## 이미지

- 텍스처는 GX TPL(매직 `00 20 AF 30`)입니다. `tpl/`, `common/`의 파일에 그대로 있거나, `.rec` 묶음과 `SZ00` 압축 파일(`.epz`, `.paz`, `.mpk`, `.mdz` 등) 안에 들어 있습니다.
- `SZ00`: `SZ00`, `u32 원래 크기`(리틀 엔디언), 0으로 채운 0x20바이트 헤더 뒤에 zlib 데이터.
- 한글화 이미지 209장의 포맷은 CMPR(188장), RGB5A3(스테이지 제목 띠 9장), I4(홈 버튼 12장)입니다. `gxenc.py`가 CMPR은 Pillow의 DXT1 결과를 GX 배치(색 빅 엔디언, 2비트 인덱스 순서 반대, 8×8 묶음)로 바꾸고, RGB5A3·I4는 직접 만듭니다.
- 스테이지 제목 띠는 여러 이벤트 파일에 같은 그림이 들어 있어 212곳을 바꿉니다. 위치는 `tools/data/textures.json`의 `refs`(파일@TPL 위치#이미지 번호)입니다.
- 번역 대상은 `dump_textures.py`로 디스크 안 고유 텍스처 12,575종을 모두 뽑아 확인해 정했습니다.

## 배포 방식 (파일 단위 패처)

ISO를 통째로 비교하는 xdelta는 덤프·변환 형태(정본 ISO, WBFS, WBFS에서 변환한 ISO 등)마다 MD5가 달라 맞지 않고, Wii 파티션이 암호화되어 있어 크기도 큽니다(약 74MB). 그래서 게임 파일 단위로 차분을 만듭니다.

- `make_patcher.py`: 빌드한 뒤 바뀐 게임 파일 322개마다 원본과의 xdelta 차분(`-9 -S djw`)을 만들고, `data/manifest.txt`에 `모드, 차분 파일, 경로, 원본 MD5, 결과 MD5`를 적습니다. `patcher/`의 `패치하기.bat`, `patch.ps1`과 wit, xdelta3를 함께 묶어 zip으로 만듭니다. 차분 합계는 약 5.6MB입니다.
- `patch.ps1`(사용자 PC에서 실행): 게임 ID(`RDZJ01`)를 확인하고 `wit extract --psel data`로 푼 뒤, 파일마다 원본 MD5 검사 → 차분 적용 → 결과 MD5 검사를 하고 `wit copy`로 다시 묶습니다. 원본이 WBFS면 결과도 WBFS입니다.
- `SZ00` 압축 파일도 풀지 않고 파일 그대로 비교합니다.
- 검증: 원본 ISO와 WBFS 양쪽에 zip을 푼 패처를 돌리고, 결과를 DolphinTool로 풀어 모든 파일을 빌드 결과·원본과 비교했습니다. 다른 파일은 다시 묶을 때 새로 만들어지는 `sys/fst.bin`뿐입니다.

## 시험용 ISO (개발용)

`inplace.py`는 원본 ISO의 배치를 유지한 채 바뀐 파일만 교체해 시험용 ISO를 빨리(약 1분) 만듭니다.

1. `wit`으로 배치를 유지한 채 복호화합니다.
2. 바뀐 파일을 원래 자리에 덮어씁니다. 원래 자리보다 커진 파일(116개)은 FST 뒤의 빈 공간(원본이 쓰지 않는 앞쪽 약 300MB)으로 옮기고, FST의 위치와 크기를 고칩니다.
3. 바뀐 2MB 그룹의 H0·H1·H2 해시를 직접 계산해 기록하고, `wit`으로 암호화합니다.
4. 원본 ISO 복사본에 바뀐 그룹만 옮기고, H3 표와 TMD 해시를 고친 뒤 가짜 서명합니다.
